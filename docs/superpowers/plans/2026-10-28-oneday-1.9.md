# OneDay 1.9 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development with disjoint ownership and a final whole-branch review. Higher-level instructions authorize parallel independent implementation and continued publication.

**Goal:** Deliver the user's 1.9 keyboard, calendar, motion and previously queued UI improvements to the existing Site.

**Architecture:** Extend the existing vanilla modules. A shared swipe controller serves the main workspace and Day detail; a new calendar module owns sourced calendar metadata and overrides the legacy renderer. Keep status transitions on the existing store path and preserve local optimistic feedback.

**Tech Stack:** Vanilla browser JS/CSS, Node behavioral tests, Python assembly, Sites official source/build/publish helpers.

**Spec:** `docs/superpowers/specs/2026-10-28-oneday-1.9-design.md`

## Global Constraints

- Existing vanilla JS/CSS and current data schema; no new runtime dependency.
- Use cohesive functions. Extract reusable behavior or a meaningful boundary, not one-off fragments. Validate unknown input at its owning boundary.
- Keep original Site identity, access policy, actual task data, draft recovery and existing 1.8 interaction behavior.
- Isolated QA data only. No destructive production testing.
- No shell-driven browser automation; root owns native browser QA.
- Do not commit another worker's changes. Root owns build registration, version metadata and publication.

## Review Focus

- IME composition, nested lists and native undo must preserve canonical Markdown and the caret (Task 1).
- Calendar year coverage and adjusted working weekends must not mislabel normal weekdays (Task 2).
- A canceled swipe, report draft or active editor must not lose data or trigger another control (Tasks 3–4).
- A reschedule conflict or failed status write must not invent elapsed work or persist completion against a rejected schedule (Task 4).
- Mobile headers, fullscreen dialogs and weighted month rows must stay within a 390 px viewport (Tasks 2–4).

### Task 1: Keyboard Markdown

**Files:** Own `src/lite/editor.js`, Markdown-related portions of `src/lite/core.js`, new `src/lite/editor-keyboard.css`, relevant/new editor tests. Do not edit app.js or build files.

**Interfaces:** Existing `OneDayLiteEditor.mount` API remains. Editor consumes events before the document focus trap using preventDefault/stopPropagation; root/nav owner adds a defaultPrevented document guard. New CSS registered by root. Nested list HTML must serialize back without flattening; untouched tables retain original source.
