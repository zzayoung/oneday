# OneDay 1.9 — keyboard editing, fluid navigation and a useful calendar

Baseline: 1.8.0 / Site version 5 / `3134f99a61fc7e1e708ebb97e9cb2f2d82e0f605`. User explicitly requested implementation and continued publication to the original Site.

## Scope and behavior

1. The live Markdown editor supports Tab / Shift+Tab indentation, nested ordered/unordered/check lists, Enter continuation and empty-line exit for list, quote, heading and code contexts. Preserve selection, composition, canonical Markdown, drafts, uploads, tables and undo. A lone `-` at the start of a line opens a keyboard format menu (arrows, Enter, Escape); normal typing and `- ` remain natural. Include useful standard formatting shortcuts and discoverable keyboard help.
2. Explicit rescheduling into a completely elapsed time interval marks that task completed. A schedule spanning the current time must not be marked complete. Moving a completed task to a current/future interval reopens it without automatically starting a timer. Moving to the todo coverflow clears its schedule and returns it to pending. Apply rules only after the final conflict-resolved schedule is accepted; never fabricate time logs from planned duration and never silently complete tasks because a clock ticked. Preserve immediate optimistic presentation and existing conflict handling.
3. A visible icon button toggles fullscreen and exits it, including from the Day window. Use native fullscreen when available and a meaningful expanded in-app layout when unsupported. State follows native fullscreen exit.
4. Tasks top tabs (日历 / 看板 / 统计), record category tabs and Day detail tabs (任务内容 / 任务日志) slide continuously with the finger. Release commits or springs back. Click and keyboard navigation remain usable. Respect editors, controls, card dragging, horizontal scrolling, vertical page scrolling, reduced motion and draft preservation.
5. The calendar labels verified mainland China holidays, adjusted working days, lunar dates and solar terms. Distinguish past and future dates. Give the current Monday–Sunday week more area/information, and emphasize today with an icon. Keep an accessible seven-column month and usable compact phone layout. Official holiday arrangements are year-scoped; do not invent future notices. Use primary government / Hong Kong Observatory sources and retain attribution in documentation.
6. Complete the previously queued 1.9 backlog: semantic icons for quadrant choices, status choices, content/log tabs, record category, content entry and duration; move record filters into the top title bar; make the record-card body directly open the record and remove the redundant 打开 button. Preserve inner links, checkboxes and more actions.

## Constraints

- Existing vanilla JS/CSS and current data schema; no new runtime dependency.
- Use cohesive functions. Extract reusable behavior or a meaningful boundary, not one-off fragments. Validate unknown input at its owning boundary.
- Keep original Site identity, access policy, actual task data, draft recovery and existing 1.8 interaction behavior.
- Scheduling strings are wall-clock plan values; compare to the user's local day/time consistently with the existing timeline.
- Isolated QA data only. No destructive production testing.
- Physical mobile keyboard, vibration and OS browser fullscreen depend on the device; state exactly what was tested.
- User authorization covers implementation and original Site publication. Do not pause for additional plan approval.

## Acceptance

Meaningful behavior regressions for keyboard editing, calendar data/layout decisions, swipe commit/cancel/exclusions, fullscreen lifecycle and schedule status transitions; native browser checks for keyboard editing and desktop/390 px layout; full existing suite; production assembly and official Sites build; published source commit/version verification.
