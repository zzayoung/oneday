# OneDay 1.6：完成新建、编辑、排期和删除

## 授权与目标

用户已明确要求在当前对话沿旧需求继续实现，并追加删除任务能力。实现并验证后更新既有 OneDay Site；保留 project_id、网址和私人访问范围。

基线：应用 1.5.0，提交 `4e45cec1f44028c9e61d9d765b301dd4e4a41dfb`，已有 253 项回归通过。当前目录是本对话单独恢复的源码副本，开发分支 `oneday-1.6`。

## 必须实现

- 新建任务只有一个大“要做什么”编辑区，不再分标题/正文；无安排日期、开始、结束输入框。
- “计划干多久”滑条最小 10 分钟、步长 10 分钟、最大 480 分钟，默认 60 分钟。
- 时间轴点击新建从点击位置开始，结束由时长计算；全局 +、/ 快捷键、普通新增/子任务新增没有 start/end，是待分配任务。日期上下文不能偷偷产生全天计划。
- 全局与时间轴入口都保留文本草稿、计划时长；当前入口决定本次时间，旧草稿不得覆盖新的点击位置。跨午夜按真实下一天保存，不裁掉时长。
- 完整 Markdown 作为任务内容；首行纯文本截取最多 300 字作为现有任务标题字段。旧任务标题和正文在单编辑区完整保留，读取时组合，无批量数据迁移。
- 普通任务详情和日视图使用同一个实时 Markdown 编辑器；修复换行、光标、中文 composition、快捷格式/清单的具体问题。保留现有附件、草稿和自动保存。
- 修复时间轴拖动/边缘缩放后的误关闭；移动、缩放、点击新建统一 10 分钟刻度，不改变已有精确时间的存储含义。
- 无日期待分配任务在日视图顶部可见并能安排；有明确安排动作，不只依赖桌面拖放。
- 放大任务/时间字号，突出选中任务右侧编辑面板；桌面和窄屏都要可读。
- 普通任务详情和日视图选中后有明显删除入口。删除进入既有回收站，支持撤销、恢复。带子任务提示影响数量；正在计时的任务明确提示先暂停并删除，执行失败清晰保留当前状态。

## 实现选择

延续原生 JS 模块、既有 store 和云后端；不替换技术栈，不增加编辑器依赖，不变更数据库 schema。新内容完整存 `任务详情`，`任务标题`是首行派生值。已有分离内容在首次编辑时自然写入新形式，避免全量迁移。编辑器继续原位 Markdown 渲染，针对实测缺陷修复；不引入并排预览作为替代。

复用接口：`C.taskTitle(markdown)` 派生首行；`C.taskContent(task)` 返回完整编辑文本（新记录直接正文，旧记录组合标题与正文）。`L.deleteTask(id)` 是详情、时间轴和更多菜单共用的可恢复删除动作，返回是否已删除。

## 边界与验收

保留已有排期冲突选择、执行计时、便签、附件与回收站。不给推测性的并发增加机制。验证有具体输入/输出的业务行为，视觉调整用页面验收而不写镜像 CSS 测试。

需要覆盖：无安排创建、10/60/480 分钟、跨午夜、旧草稿新入口、第一行更改后的列表标题、旧内容完整保留、任务移动/缩放保持日视图、删除/撤销/子任务/运行任务、中文换行与 Markdown 光标、保存后重开。测试数据只在本地 QA 使用。
