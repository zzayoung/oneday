## Markdown 键盘编辑

| 操作 | 行为 |
| --- | --- |
| Tab / Shift+Tab | 缩进、减少列表层级；支持有序、无序、清单及多行列表选区 |
| Enter | 延续列表编号、清单、引用及当前标题层级 |
| 空格式行再次 Enter | 退出当前格式；嵌套列表先退回上一级 |
| 空段落输入 `-` | 显示格式菜单：列表、编号、清单、标题、引用、代码块、分隔线 |
| ↑ / ↓、Enter、Escape | 选择、应用、关闭格式菜单 |
| Ctrl/⌘ B、I、K | 加粗、斜体、插入链接 |
| Ctrl/⌘ + 反引号 | 行内代码；多行选区应用代码块 |
| Ctrl/⌘ Z、Shift+Z 或 Ctrl Y | 撤销、重做 |
| Escape 后 Tab / Shift+Tab | 从编辑器移出焦点；若格式菜单打开，先 Escape 关闭菜单 |

保留输入法组词、行内格式和光标位置。代码块中的 Enter 保留原样换行；标题和嵌套列表在失焦、重新进入以及保存后仍保留结构。撤销记录最多保留 100 个快照。

## 排期与状态

- 任务被重新安排到已经结束的时间段：自动改为「已完成」。以结束时间判断；仍跨越当前时刻的任务不会提前完成。
- 已完成或已结束的任务重新安排到当前／未来时间段：恢复「待开始」。普通进行中、暂停任务排到未来时保留已有状态。
- 拖回上方待办 Coverflow：清除排期，恢复「待开始」。
- 排期与状态先在界面同时显示，再保存；后续返回不会覆盖更晚一次拖动。仅接受最终通过冲突处理的排期。
- 重新排期不会自动开始计时，也不会把计划时长记作真实工作时长；实际时间日志沿用已有状态切换逻辑。
- 跨设备修改、写入失败保留明确的错误反馈；计划已保存但状态未保存时会分别说明，避免伪装为全部成功。

## 跟手切换与手机全屏

- 任务页日历／看板／统计、记录分类、单日详情的内容／日志，均使用连续位移、松手完成或回弹的切换动画。
- 顶部 Tab 条可直接拖动，点击和键盘切换也使用同一过渡。看板、横向表格、代码区和分类条溢出时保留自身的横向滚动；编辑器输入、卡片拖动不被页面切换抢占。
- 取消切换保留原内容和滚动位置，切换前后保留编辑草稿。
- 主界面及弹窗增加进入／退出全屏图标。浏览器允许时使用原生全屏；不支持或拒绝时使用可退出的「展开视图」。展开状态可再次点击图标或按 Escape 退出。
- 手机仍保留搜索、全屏、设置入口；记录页标题栏分为品牌／操作和分类两行。

- 格子里的执行水位继续代表真实执行时长，不使用计划时长。

## 实现口径与复核决定

以下记录设计与评审中的决定及判断错误时的代价，便于后续迭代：

1. 独立模块并行开发、共享文件由单一负责人修改；判断错误会增加合并与接口返工，因此各模块和整版均复核。
2. 根据用户明确要求继续 1.9 和此前同步 Site 的授权，完成后直接更新原站点；若发布时机理解有误，需要回退版本。
3. 终态任务移到当前／未来恢复待开始，不自动计时；若用户希望保留终态，需要调整这条规则。
4. 原「卡片点击可以直接打卡」按「移除打开按钮」的上下文解释为直接打开内容；若实际指完成打卡，需要另行明确动作语义。
5. Tab 默认缩进，Escape 后 Tab 提供焦点退出；额外一步换来编辑缩进与无鼠标离开的兼容。
6. 发布元数据、生产拼装、验收入口移除和部署核对由最终发布阶段处理；漏做会造成版本或部署内容不一致，因此作为发布检查项。
7. 未用桌面模拟结果替代真实手机硬件验证；特定手机上的输入法、震动、全屏差异仍可能需要后续适配。
8. 旧 agenda 独有的 `plan-today` 操作已不可从当前日历进入，不在本版改动该废弃入口；以后恢复 agenda 时须接入共用排期状态逻辑。
